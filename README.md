## 一、学习方式

**① 分层推进**
按底层到应用的顺序：C 语言基础 → 外设（GPIO / UART / I2C / SPI）→ RTOS → 通信协议 → 综合项目。每层以实际运行验证通过为完成标志。

**② 多轮重写并记录错因**
以链表为例，累计重写 5 轮以上，每轮记录暴露出的具体问题（空链表未判、双指针不一致、边界处理等）。`04_linked_list/` 下的 `rewrite_v1/v2` 与 `*_drill` 即该过程的留档。

**③ 脱离参考重建**
参考代码运行通过只代表理解。检验方式为关闭参考、从空白文件重新实现；无法完成时再回查参考。

**④ 借助 AI 协作**
使用 AI 辅助获取参考实现、定位错误、审查结构；代码由本人编写、理解并上板验证。

## 六、综合项目：工业现场数据采集终端（`13_stm32_project`）

**目标**：把分散学过的外设、RTOS 与通信协议串联为完整链路，打通"传感器 → 处理 → 显示 → 通信"整条数据流。

**技术栈**：STM32F103RCT6 + FreeRTOS + AHT20(I2C) + OLED(SPI) + PWM 蜂鸣器 + 4×4 矩阵键盘 + Modbus-RTU 从站

**自主完成的部分**：
- **驱动层**：AHT20 温湿度驱动、蜂鸣器 PWM 驱动（PB8 / TIM4_CH3）、4×4 矩阵键盘驱动（GPIO 扫描 + 非阻塞消抖）
- **Modbus-RTU 从站协议层**（`User/APP/modbus_slave.c/.h`）：收帧状态机、CRC16 校验、03 读保持寄存器应答、异常码处理、寄存器表接口
- **FreeRTOS 任务架构**：采集 / 显示 / 按键 / 协议四类任务划分，任务间通过队列与寄存器接口通信
- **按键状态机**：设置流程状态机 —— 进入设置 → 选择对象 → 数字输入 → 确认 / 退格
- **寄存器表设计**：温湿度、报警阈值、报警状态、系统状态等 40001-40007 的分配与读写接口

**基于例程的部分**：工程结构、ST 官方 HAL 库、IIC / OLED / LED / KEY / TIMER 驱动层。例程原以板载 LCD 显示两个任务的计数，本项目改为 OLED 显示温湿度与阈值。

## 七、调试记录

**1. I2C 读 AHT20 一直失败**
逐层排查后确认是软件问题，共 5 处：
- 从机地址方向位写错，读写没有区分
- SCL 时钟宏用错，端口与引脚不匹配
- 初始化命令残缺，少了校准参数
- 缺少"触发测量 → 读取结果"的事务，直接去读状态字
- 读地址拼接错误

修正后正常读出温湿度。

**2. 串口发 Modbus 帧完全没反应**
串口助手未勾选 Hex 模式，实际发出的是 24 个 ASCII 字符，帧长和校验都不对，从站按错误帧静默丢弃。改回 Hex 发送后正常。

**3. Modbus 06 功能码用例不返回异常帧**
判断分支写成了 `if (buf[1] != func)`，自身比较恒为假，异常应答分支从未执行。改为功能码白名单判断后修复。

**4. 矩阵键盘扫描写不出来**
用循环扫描时缺少"行号 → 引脚"的映射，补上 `s_row_pins[]` / `s_col_pins[]` 两张查表后解决。
